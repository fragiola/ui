Pick a colour and a level of each design axis. The sample is the registry's
own components, re-coloured and re-measured as you change them. Then copy the
CSS and the attributes that reproduce it in your project.

For a larger preview, open the example in the gallery and use **Fullscreen**.

## From the builder to your project

<Steps>
<Step>

### Pick a colour

A colour is a palette pair, generated from one hue by `generatePalette`
(the registry's `colour` helper). `palette-brand` is for solid things: a
button, a badge, a progress bar. `palette-surface-brand` is for controls on
the floor: a neutral box whose focus ring and "on" state carry the colour.
Every pair is checked against WCAG AA with the same maths the registry's
contrast guard uses on the shipped palettes, and the builder says so.

</Step>
<Step>

### Set the axes

Spacing, radius, typography, elevation and motion are `data-*` attributes on
`<html>`, each with a few named levels; `default` is no attribute at all.
See [Design axes](/docs/architecture/design-axes).

</Step>
<Step>

### Paste the CSS, set the attributes, apply the class

Paste the **CSS** next to your other palettes and add both names to the
palette group in `lib/cn.ts`. Put the **HTML** attributes on `<html>`. Then
carry the classes as in **Usage**.

</Step>
</Steps>

<Callout type="info">
**One class, nothing else.** No component has a colour variant or an axis
prop. A colour is a palette, applied by class; a level is an attribute on an
ancestor. Changing your design never means editing a component.
</Callout>

## Generating at runtime

The builder uses the same helper you can install:

```bash
npx shadcn@latest add @fragiola/colour
```

```ts
import { generatePalette, serializePalette } from "@/lib/colour/palette";

const palette = generatePalette({ name: "brand", hue: 160, chroma: "vivid" });
palette.pass; // every pair clears AA
const css = serializePalette(palette); // inject in a <style>, or write to a file
```
