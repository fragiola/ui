---

Fragiola distributes through shadcn's registry format and CLI. There is no
`@fragiola/ui` package to install — the CLI copies source files into your
project, and you own them from that point on.

## Add the registry

Add the `@fragiola` namespace to your `components.json`:

```json
{
  "registries": {
    "@fragiola": {
      "url": "https://fragiola.com/r/{name}.json"
    }
  }
}
```

For local development against a checkout of this repository, build the
registry with `pnpm registry:build` — it writes `packages/registry/dist/r/` —
and point at any static server rooted at `packages/registry/dist`:

```json
{
  "registries": {
    "@fragiola": {
      "url": "http://localhost:3000/r/{name}.json"
    }
  }
}
```

## Bases

Fragiola UI offers every component on two primitive libraries, its **bases**,
as shadcn/ui does with Base UI, Radix and React Aria:

| base | primitives | registry URL |
|---|---|---|
| **Fragiola Primitives** (default) | `@fragiola/primitives-react` | `https://fragiola.com/r/{name}.json` |
| Base UI | `@base-ui/react` | `https://fragiola.com/r/base/{name}.json` |

Both bases ship the same items under the same names: the same parts, classes,
`data-slot` names and composition, so code written against one runs on the
other. Only the primitive wiring inside each component differs, and where the
two libraries behave differently by design, the component's page says so
under **Bases**. The namespace stays `@fragiola` on both; the URL chooses the
base.

A few components exist only in Fragiola Primitives (Segmented Control, for
one). They are **primitives-backed**: one shared source that uses
`@fragiola/primitives-react` on both bases, so the Base UI registry installs
that package too for them, and both bases keep the same catalog. Their page
says so under **Bases**. For Base UI:

```json
{
  "registries": {
    "@fragiola": {
      "url": "https://fragiola.com/r/base/{name}.json"
    }
  }
}
```

The base switch in the sidebar (and in the examples gallery) shows every
example on the base you choose, and adds the base's `components.json` entry
under each install command. Locally, `pnpm registry:build` writes Base UI's
items to `packages/registry/dist/r/base/`.

### Installed before Fragiola Primitives was the default?

Items installed before this change are Base UI's. To keep them on Base UI,
point the namespace at the Base UI URL above before adding anything else. To
move to Fragiola Primitives, add the items again with the default URL: the
CLI asks before it overwrites a file you have edited.

## Install an item

```bash
npx shadcn@latest add @fragiola/text
```

The CLI resolves the dependency graph recursively. Installing `text` pulls
`cn`; installing a component that depends on `text` afterwards writes only the
files that are missing. Every dependency resolves inside `@fragiola` — the CLI
never reaches the default shadcn registry for a Fragiola item.

## What you get

Files land under your `components.json` aliases, so with the defaults they go
to `src/` when the project has one and to the project root otherwise:

| what | lands in | with default aliases and `src/` |
|---|---|---|
| components | your `ui` alias | `src/components/ui/` |
| atoms and style families | your `components` alias | `src/components/atoms/`, `src/components/families/` |
| `cn`, `get-token` | your `lib` alias | `src/lib/` |
| hooks | your `hooks` alias | `src/hooks/` |
| `global.css` and palettes | `styles/`, under `src/` when it exists | `src/styles/`, `src/styles/palettes/` |

Imports inside the files are rewritten to your aliases, so they resolve
wherever your aliases point.

## Wire the CSS

The CLI writes `styles/global.css` and each palette as a separate file; it
does not edit your CSS entry. Import them once, after Tailwind — paths are
relative to your entry, here a Next app's `src/app/globals.css`:

```css
@import "tailwindcss";
@import "../styles/global.css";
@import "../styles/palettes/surface.css";
@import "../styles/palettes/raised.css";
```

Add a palette's `@import` when you install it. Adding an item again does not
overwrite a file you have edited — the CLI asks first.

## No versioning

The registry format has no `version` field. Whoever installs keeps a frozen
copy. That is inherent to copy-paste distribution, and it is accepted
deliberately — pretending otherwise would be worse than saying it plainly. If
it becomes a real problem, that is when a custom CLI would be worth building,
not before.

## Using an AI agent

Your agent can install and compose these items for you. The Fragiola MCP server
tells it which components exist, how to install each and how the headless
libraries differ from this registry's source, and the agent skills teach it
the palettes and the composition rules. See [AI agents](/docs/getting-started/ai-agents).
